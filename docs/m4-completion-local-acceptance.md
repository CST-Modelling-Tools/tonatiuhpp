## Implementation boundaries and remaining review

1. Shared `PhotonExportFileService` discovers the production File plugin without a widget, validates name/size/path choices, and inspects completed File output using a streaming SHA-256 manifest for safe append. Real GUI and script append paths reject changed/missing/extra files; a failed/incomplete export never becomes an accepted append checkpoint.
2. The legacy File plugin emits nonmodal diagnostics, probes writability with unique temporary files, refuses symlink targets, and limits segmented deletion to generated numeric segment filenames. GUI-specific overwrite consent remains in the GUI adapter; CLI/script are fail-closed.
3. Direct CLI and shared GUI/headless script hosts accept File basename, segmentation, cumulative append, selected surfaces and a guarded 10-million-ray request limit. The CLI, GUI-script and interactive File outputs are physically equivalent for the fixed-seed fixtures tested; arbitrary options/huge exports are not universally validated.
4. Existing common nonvisual interception and flux-grid services from M3 remain in use; this package does not introduce a second ray tracer, flux algorithm, photon format or RNG policy.
